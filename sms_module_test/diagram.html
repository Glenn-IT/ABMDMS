Can this SIM800L actually send a text?

One question, four tests, on a rig with nothing else attached. The motion system already has its SMS code written — but code cannot fix a module that has no 2G signal, no load, or not enough current. So the module gets proven on its own first.

Arduino Uno SIM800L V2.2 (UNV) · 5 V external 5 V supply 1000 µF 4× PIR sensors XAMPP · MySQL dashboard

01The rig

Five wires and a capacitor. The module never touches the Arduino's 5 V pin — it draws up to 2 A in bursts while transmitting and the Uno's regulator can give about a quarter of that.

Amber is power, grey is ground, dark is data. The capacitor has two legs bridging the two power rails — drawn or built inline on the 5 V wire it blocks DC and the module never powers up at all.

Every connection in the rig. Same pins as motion_sensor.ino, on purpose.

02Three faults that imitate a dead module

Nearly every "the SIM800L is broken" story is one of these. All three produce the same symptom — total silence from AT — which is why they are worth ruling out before anything else.

Power

Fed from the Arduino

The Uno's regulator manages about 0.5 A. The module wants 2 A in bursts, browns out, and reboots mid-message — often after appearing to work at idle.

Ground

No common ground

Both halves are powered, both look alive, and neither can hear the other. Serial data has no shared reference. Join all three grounds at one point.

Capacitor

Cap wired in series

It belongs across 5Vin and GND, storing energy for the transmit burst. Placed in line with the 5 V wire it blocks DC entirely — nothing powers up.

04The four tests

Each one depends on the one before it. A failure tells you which layer is at fault, which is the whole reason for running them separately.

A
Power and status LED
Multimeter and eyes. Proves the supply holds up and a 2G network accepted the SIM.
gate: ~3 s blink, 5 V steady for 2 min
B
Manual AT commands sim800l_passthrough.ino
You type, the module answers. Proves the wiring is right and that it can send a message.
gate: a real text arrives on your phone
C
Automatic self-test sim800l_selftest.ino
The same six checks, hands-free, with a verdict. Run it three times — a module that passes once and fails twice has a power problem.
gate: ALL PASS, repeatably
D
Laptop off
Arduino on the power bank, USB unplugged. This is the point of the whole feature: the Arduino sends the SMS, the website only records it.
gate: text arrives with no computer involved

05Test B, command by command

Serial Monitor at 9600, line ending set to “Both NL & CR”. Get that dropdown wrong and the module ignores everything you type — the most common false alarm of the whole build.

1ATOK
2AT+CPIN?+CPIN: READY
3AT+CSQ+CSQ: 17,0  (>10; 99 = none)
4AT+CREG?+CREG: 0,1
5AT+CMGF=1OK
6AT+CMGS="+639XXXXXXXXX">
7your message, then ENDsends Ctrl+Z
8—+CMGS: 42 → phone buzzes

The Arduino IDE cannot type Ctrl+Z, so the passthrough sketch converts the word END into it. Type RESET to pulse the module's reset pin.
